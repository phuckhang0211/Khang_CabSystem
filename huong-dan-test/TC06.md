# TC06 — Health và readiness

## Mục tiêu
Chứng minh health Gateway, readiness của 16 thành phần và lỗi 503 khi một service dừng.

## Điều kiện trước
Mở PowerShell tại thư mục gốc; Compose thường có 17 container healthy. Không cần token. Sau bài thử phải khởi động lại `notify-service`.

## Các bước
```powershell
$base = 'http://localhost:3000/api/v1'
$health = Invoke-RestMethod "$base/health"
$ready = Invoke-RestMethod "$base/ready"
$services = Invoke-RestMethod "$base/health/services"
"health=$($health.status) ready=$($ready.status) components=$($services.components.Count)"
$out = Join-Path $env:TEMP 'tc06-ready.json'
docker compose stop notify-service
try {
    $code = curl.exe -s -o $out -w '%{http_code}' "$base/ready"
    "stopped-ready=$code error=$((Get-Content $out -Raw | ConvertFrom-Json).error.code)"
} finally {
    docker compose start notify-service | Out-Null
    Remove-Item -LiteralPath $out -ErrorAction SilentlyContinue
}
for ($i = 0; $i -lt 30; $i++) {
    if ((docker compose ps notify-service --format json | ConvertFrom-Json).Health -eq 'healthy') { break }
    Start-Sleep -Seconds 2
}
$ready = Invoke-RestMethod "$base/ready"
"restored-ready=$($ready.status) notify=$((docker compose ps notify-service --format json | ConvertFrom-Json).Health)"
```

## Kết quả mong đợi
Ban đầu `/health` là `healthy`, `/ready` là `ready`, `/health/services` có 16 component (7 service, 7 DB, Redis, RabbitMQ). Dừng Notify làm `/ready` trả HTTP 503 với `NOT_READY`; sau `start` và healthcheck, `/ready` lại `ready`. Ba route health không bị rate limit.

## Cách chụp minh chứng
Chụp ba dòng trạng thái ban đầu, lúc dừng và sau khôi phục, cùng `docker compose ps notify-service`; gợi ý `TC06-ready-503-recovery.png`.
