# TC04 — Giao tiếp giữa microservice

## Mục tiêu
Phân biệt RPC gRPC đồng bộ với event RabbitMQ bất đồng bộ trong luồng đặt xe.

## Điều kiện trước
Mở PowerShell tại thư mục gốc; Compose thường đã chạy và seed đã có. Không cần token. Không gọi trực tiếp cổng gRPC từ host.

## Các bước
```powershell
Select-String -Path contracts/proto/*.proto -Pattern 'rpc ' | Select-Object -First 12
docker compose logs --tail=30 booking-service
docker compose logs --tail=30 trip-service
```
Đối chiếu các RPC trong `contracts/proto` với bảng sau và `docs/SPEC.md` §5–§6.

| Kiểu | Bên gửi → bên nhận | Ví dụ |
|---|---|---|
| gRPC đồng bộ | Gateway → Auth | `Login`, trả token ngay trong response REST |
| gRPC đồng bộ | Booking → Payment | `CreatePayment`, trả `paymentId` trước khi trả Booking |
| gRPC đồng bộ | Booking → Driver | `SearchNearbyDrivers`, `TryAssignDriver` |
| RabbitMQ bất đồng bộ | Payment → `booking.q`, `notify.q` | `payment.completed`: mở matching và tạo notification |
| RabbitMQ bất đồng bộ | Booking → `trip.q`, `notify.q` | `booking.assigned`: tạo Trip sau accept |
| RabbitMQ bất đồng bộ | Trip → `booking.q`, `notify.q` | `trip.completed`/`trip.canceled`: đồng bộ Booking |

Exchange là topic durable `ride.events`, routing key bằng event type; producer commit DB trước khi publish, consumer ack sau xử lý. Log chỉ minh họa tiến trình service; để thấy event lịch sử cần chạy flow Postman TC15–TC18 hoặc xem RabbitMQ ở TC07.

## Kết quả mong đợi
Lệnh đầu liệt kê các khai báo `rpc` trong proto. Hai lệnh log chạy được; khi vừa khởi động, Booking/Trip ghi log mở gRPC. `booking.assigned` đi qua queue rồi Trip mới được tạo, khác RPC trả kết quả ngay.

## Cách chụp minh chứng
Chụp proto hiển thị RPC, bảng giao tiếp và terminal log; gợi ý `TC04-grpc-rabbitmq.png`. Không chụp token hoặc payload chứa dữ liệu cá nhân.
